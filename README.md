## What is Hera?

You solve a problem with Claude Code or Codex. A week later, you need the same
reasoning, but the useful part is buried in an old conversation. You either
search through transcripts or explain everything again.

Hera gives those sessions a place to go. It files notes as Markdown, searches
them when you ask a new question, and shows the agent short pointers to pages
that may help. The agent can open the original page for the full context. A
citation in its answer tells Hera which notes proved useful.

The vault is yours: the pages live under [`wiki/`](wiki/), and the search index
is one local SQLite database.

## The memory loop

1. **File the session.** When a Claude Code or Codex session ends, Hera distills
   the conversation into a source note and related concept or
   entity pages. You can also ingest an article, transcript, image, or note with
   `hera-ingest`.
2. **Find the right page.** At the next prompt, Hera searches your vault and
   adds a few page titles, summaries, and absolute file paths to the agent's
   context. It can also flag an unresolved contradiction beside a result.
3. **Keep what helps.** When the agent cites a page as `(Source: [[Title]])`,
   Hera records that citation. Those scores inform ranking and an optional,
   explicitly invoked prune review. Archived pages remain restorable.

Hera combines keyword search and local embeddings to find pages; the agent
receives pointers rather than a dump of the whole vault. The [retrieval
reference](docs/RETRIEVAL.md) explains the ranking and thresholds.

## Install

You need **Git**, **Claude Code or Codex**, and **Python 3.11+ with SQLite
extension loading**. On macOS, use Homebrew Python; the python.org macOS build
lacks extension loading. On Windows, use python.org Python rather than the
Microsoft Store build. Hera runs on Windows 10/11, macOS, and Linux.

```bash
git clone https://github.com/randyren278/hera.git
cd hera
python install.py
```

The installer creates a virtual environment and the local database, provisions
Ollama and its `nomic-embed-text` embedding model if needed, and registers Hera
for both Claude Code and Codex. It links the same five `hera-*` skills into both
clients on macOS and Linux; Windows uses managed copies. The hooks run from
this vault, so edits to their source take effect without a second install.

Codex asks you to review new hooks once. Restart Codex, open `/hooks`, and trust
the four Hera hooks to enable automatic recall, scoring, and session filing.
Existing global agent instructions are preserved. If Ollama is missing, an
interactive install asks before running Ollama's official installer; a
non-interactive one (CI, or an agent running it) skips it unless you pass
`--install-ollama`. Without Ollama the install still completes: hooks stay
silent and session filing waits until Ollama is running, then catches up.

## First use

Open Claude Code or Codex in any project. In Claude Code, run `/hera-setup`;
in Codex, ask it to use the `hera-setup` skill. That finalizes the vault's
purpose in `wiki/overview.md` and optionally connects a team space. Then point
`hera-ingest` at a note or source you want to keep. Ask a question about it in
a later turn; Hera's prompt hook will offer the relevant page as a pointer.

The everyday loop needs no command after setup. The skills are there for
intentional work:

| Skill | When to use it |
| --- | --- |
| `hera-ingest` | Add a file, URL, image, or batch of sources |
| `hera-conflicts` | Review and resolve claims that disagree |
| `hera-prune` | Review archive candidates; nothing is deleted automatically |
| `hera-team` | Stage a public-safe copy for a team, remove your own published pages, or retrieve team notes |

Check the installation from the vault directory:

```bash
python scripts/hera_cli.py hera_db --doctor
```

For manual ingest or publish commands launched from Codex, set
`HERA_LLM_BACKEND=codex` so their extraction uses Codex. The Codex session hook
sets this automatically when it files a conversation.

## Your notes, your control

- **Local source of truth.** Markdown pages and the SQLite index stay in the
  vault. Extraction sends source text to the selected Claude or Codex model;
  embeddings are generated by local Ollama.
- **Review before sharing.** Team space is optional. `hera-team add` strips and
  stages a separate public copy, shows you the diff, and waits for explicit
  approval before a push. Team pages use a separate `team.db` index.
- **Conflicts stay visible.** New claims that disagree with existing pages enter
  a review queue. Hera does not silently replace the old claim.
- **Archiving is deliberate.** `hera-prune` runs only when invoked. It proposes
  a middle band of older pages, and archived Markdown remains
  available to restore.

`HERA_OFF=1` turns off Hera's hooks for one process. `python install.py
--uninstall` removes Hera's managed hooks, skills, locator, and guidance links
without deleting your notes or database.

## Under the hood

Four hooks connect each agent to the same vault: session start surfaces recent
context, prompt submission retrieves relevant pages, stop scores citations,
and session end files the conversation. The [hook reference](docs/HOOKS.md)
describes the events and failure behavior. The [architecture](docs/ARCHITECTURE.md)
and [data model](docs/DATA-MODEL.md) explain the Markdown, SQLite FTS5,
`sqlite-vec`, and Ollama pieces.

When you enable team space, `team_index.py` maintains its separate `team.db`;
team pages never enter your personal `hera.db`.

For a guided tour, start with [onboarding](docs/ONBOARDING.md). The
[documentation map](docs/README.md) links the installation details, pipelines,
and design decisions. The [global install guide](docs/GLOBAL_INSTALL.md)
shows exactly which files the installer changes in each client.
